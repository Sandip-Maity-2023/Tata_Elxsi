## **CASE STUDY 1**

### **Self-Healing Machines: Predictive Maintenance for a Connected Fleet**



---

### **Background & Problem Statement**

A fleet of connected machines—such as trucks, buses, or industrial compressors—continuously streams sensor data including vibration, temperature, motor current, pressure, and RPM. Currently, failures are mostly caught after a breakdown or through fixed service intervals, leading to unplanned downtime and higher maintenance costs.

The team must build a **closed-loop system** that ingests this sensor data, detects early signs of degradation, predicts how much useful life a machine has left, and then automatically raises a maintenance work order with a human stepping in only for exceptions.

---

### **What the Team Must Demonstrate**

| Layer | What to build |
| --- | --- |
| **Data Engineering** | Read the sensor data (batch or streaming), clean it, handle missing values and basic noise, and create simple rolling-window features (e.g., averages, trends) for the model.

 |
| **Machine Learning** | Detect abnormal behavior and predict the **Remaining Useful Life (RUL)** — how many cycles a machine has left before failure.

 |
| **MLOps** | Track experiments and model versions, and show a simple retraining flow when new data arrives, along with a basic monitoring view.

 |
| **Agents (non-LLM)** | A rule-based **Triage Agent** that reads the model output, decides the severity, and automatically creates a maintenance work order. No LLM required.

 |

#### **Ground Rules:**

* Failures are less frequent than normal readings, so the model should handle mild imbalance.


* The pipeline should run end-to-end without manual steps once data is provided.


* Keep it lightweight — no LLM. The agent should use simple rules or thresholds.


* Use open-source tools; document the design clearly so it can be explained in a review.



---

### **Dataset**

* Use the **NASA C-MAPSS Turbofan Engine Degradation dataset**—a well-documented benchmark of medium complexity.


* It contains run-to-failure sensor readings from a fleet of engines (21 sensors + 3 operating settings), with true Remaining Useful Life values provided for evaluation.


* The dataset comes in four subsets (**FD001–FD004**) of increasing difficulty. You may choose to work with just one subset (FD001 is the simplest and a good starting point) or take on all four for a more challenging solution.


* **Official NASA Data Link:** `data.nasa.gov/dataset/cmapss-jet-engine-simulated-data`

| Criterion | Weight | Assessed on |
| --- | --- | --- |

 |

 |

 |

 |
